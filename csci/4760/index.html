CSCI 6760/4760 Computer Networks — Midterm Notes

Based on Kurose & Ross, Computer Networking: A Top-Down Approach, 7th Ed.

Chapter 1: Introduction

1.1 What is the Internet?

  • Nuts and bolts view: Millions of connected computing devices (hosts/end systems), communication links (fiber, copper, radio, satellite), packet switches (routers and switches).
  • Service view: Infrastructure that provides services to applications (Web, VoIP, email, games, e-commerce, social nets).
  • Protocols: Define format, order of messages sent and received among network entities, and actions taken on message transmission/receipt.

1.2 Network Edge

  • Hosts: Clients and servers. Servers often in data centers.
  • Access networks: Residential (DSL, cable), institutional (Ethernet), mobile (wireless).
  • Physical media: Twisted pair, coax, fiber, radio.
  • DSL: < 2.5 Mbps upstream, < 24 Mbps downstream. Dedicated line to central office.
  • Cable: HFC, asymmetric (up to 30 Mbps down, 2 Mbps up). Shared access network.
  • Enterprise: Ethernet switch, 10 Mbps – 10 Gbps.
  • Wireless: WiFi (802.11b/g: 11/54 Mbps), 3G/4G LTE (few Mbps).

1.3 Network Core

  • Packet switching: Hosts break messages into packets; packets forwarded from router to router; each packet transmitted at full link capacity.
  • Store-and-forward: Entire packet must arrive at router before it can be transmitted on next link. End-to-end delay = 2L/R (assuming zero propagation delay).
  • Queueing delay and loss: If arrival rate exceeds transmission rate, packets queue and can be dropped if buffer fills.
  • Circuit switching: End-to-end resources allocated/reserved for "call"; dedicated resources, no sharing; guaranteed performance.
  • FDM vs TDM: Frequency Division Multiplexing vs Time Division Multiplexing.
  • Packet vs circuit switching: Packet switching allows more users; great for bursty data; excessive congestion possible.
  • Internet structure: Network of networks; access ISPs, regional ISPs, tier-1 ISPs, content provider networks, IXPs.

1.4 Delay, Loss, Throughput

dnode = dproc + dqueue + dtrans + dprop
dtrans = L / R   |   dprop = d / s   |   Traffic intensity = La / R
  • Traffic intensity: ~0 → small queueing delay; →1 → large; >1 → infinite.
  • Throughput: Rate at which bits transferred between sender/receiver. Bottleneck link constrains end-to-end throughput.

1.5 Protocol Layers, Service Models

  • Internet protocol stack: Application, Transport, Network, Link, Physical.
  • ISO/OSI reference model: Adds Presentation and Session layers.
  • Encapsulation: Each layer adds header information.

1.6 Networks Under Attack: Security

  • Malware: Virus, Trojan horse, Spyware, Worms, Logic Bomb, Rootkit, Zombie, Ransomware.
  • DoS attacks: Make resources unavailable by overwhelming with bogus traffic.
  • Packet sniffing: Promiscuous network interface reads all packets (passive).
  • IP spoofing: Send packet with false source address (active).
  • SQL Injection: Injecting SQL code into application-database exchange.

1.7 History (timeline)

  • 1961–1972: Early packet-switching (Kleinrock, Baran, ARPAnet).
  • 1972–1980: Internetworking (Cerf and Kahn, Ethernet, proprietary architectures).
  • 1980–1990: New protocols (TCP/IP, SMTP, DNS, FTP, TCP congestion control).
  • 1990–2000s: Commercialization, the Web, new apps.
  • 2005–present: ~750 million hosts, smartphones, broadband, social networks, cloud.

Chapter 2: Application Layer

2.1 Principles of Network Applications

  • Application architectures: Client-server, Peer-to-Peer (P2P).
  • Processes: Program running within a host; communicate by exchanging messages.
  • Sockets: Software interface between application process and end-to-end transport protocol.
  • Addressing processes: IP address + port number.
  • App-layer protocol defines: Types of messages, syntax, semantics, rules.
  • Transport service requirements: Data integrity, timing, throughput, security.
  • Internet transport protocols services: TCP (reliable, flow control, congestion control, connection-oriented), UDP (unreliable, no frills).

2.2 Web and HTTP

  • HTTP: Hypertext Transfer Protocol; client/server model; uses TCP; stateless.
  • HTTP connections: Non-persistent (2 RTT per object), persistent (one RTT for all referenced objects).
  • HTTP request message: Request line (method, URL, version), header lines, body.
  • HTTP response message: Status line, header lines, body.
  • Methods: GET, POST, HEAD, PUT, DELETE.
  • Status codes: 200 OK, 301 Moved Permanently, 400 Bad Request, 404 Not Found, 505 HTTP Version Not Supported.
  • Cookies: Keep state; four components: cookie header in response, cookie header in request, cookie file on user's host, back-end database.
  • Web caches (proxy server): Satisfy client request without involving origin server; reduces response time and traffic.
  • Conditional GET: Don't send object if cache has up-to-date version; If-modified-since: <date>.

2.3 FTP

  • FTP: File Transfer Protocol; client/server; port 21; separate control and data connections.
  • Commands: USER, PASS, LIST, RETR, STOR.
  • Return codes: 331 Username OK, 125 Data connection already open, 425 Can't open data connection, 452 Error writing file.

2.4 Electronic Mail

  • User agents: Mail readers.
  • Mail servers: Mailbox, message queue.
  • SMTP: TCP port 25; push protocol; three phases: handshaking, transfer, closure. 7-bit ASCII.
  • Mail message format: Header lines (To, From, Subject), blank line, body.
  • Mail access protocols: POP3 (port 110, pull, download-and-delete/keep), IMAP (keeps messages on server, stateful), HTTP (gmail, Hotmail).

2.5 DNS

  • DNS: Domain Name System; distributed database; application-layer protocol; port 53; uses UDP (and TCP for zone transfer).
  • Services: Hostname to IP translation, host aliasing, mail server aliasing, load distribution.
  • Hierarchy: Root DNS servers, TLD DNS servers, Authoritative DNS servers, Local DNS server.
  • Name resolution: Iterative queries, recursive queries.
  • Caching: Name server caches mappings; TTL.
  • DNS records: A (hostname→IP), NS (domain→authoritative server), CNAME (alias→canonical), MX (domain→mail server).
  • DNS messages: Query and reply messages with same format (identification, flags, questions, answers, authority, additional info).

2.6 P2P Applications

  • Pure P2P: No always-on server; arbitrary end systems directly communicate.
  • File distribution time:
    Client-server: Dc-s ≥ max{NF/us, F/dmin}
    P2P: DP2P ≥ max{F/us, F/dmin, NF/(us + Σui)}
  • BitTorrent: File divided into chunks; tracker; torrent; rarest first; tit-for-tat.
  • Distributed Hash Table (DHT): Distribute (key, value) pairs over peers; circular DHT; peer churn.

2.7 Socket Programming

  • TCP: Reliable, in-order byte stream; connection-oriented.
  • UDP: Unreliable datagrams; no connection.
  • Socket API: socket(), bind(), listen(), accept(), connect(), send(), recv(), close().

Chapter 3: Transport Layer

3.1 Transport-Layer Services

  • Logical communication between app processes on different hosts.
  • Transport vs Network layer: Network layer: logical communication between hosts; Transport layer: logical communication between processes.
  • Internet transport protocols: TCP (reliable, in-order, congestion control, flow control, connection setup), UDP (unreliable, unordered, no frills).

3.2 Multiplexing and Demultiplexing

  • Multiplexing at sender: Handle data from multiple sockets, add transport header.
  • Demultiplexing at receiver: Use header info to deliver segments to correct socket.
  • Connectionless demux (UDP): Uses destination port number only.
  • Connection-oriented demux (TCP): Uses 4-tuple (source IP, source port, dest IP, dest port).

3.3 Connectionless Transport: UDP

  • UDP: No frills, best effort; connectionless; no handshaking; each segment handled independently.
  • Uses: Streaming multimedia, DNS, reliable transfer over UDP (application-layer reliability).
  • Why UDP?: No connection establishment, simple, small header, no congestion control, finer control over data sent, no connection state.
  • UDP segment format: Source port, dest port, length, checksum, application data.
  • UDP checksum: Detect errors; one's complement sum of 16-bit integers.

3.4 Principles of Reliable Data Transfer

  • rdt1.0: Perfectly reliable channel.
  • rdt2.0: Channel with bit errors; ACK/NAK; retransmission.
  • rdt2.1: Handles garbled ACK/NAKs; sequence numbers (0,1).
  • rdt2.2: NAK-free protocol; ACK with sequence number.
  • rdt3.0: Channel with losses; timeout; retransmission.
  • Performance: Stop-and-wait utilization = (L/R) / (RTT + L/R).
  • Pipelining: Go-Back-N (cumulative ACK, timer for oldest unacked, retransmit all on timeout), Selective Repeat (individual ACK, timer for each unacked, retransmit only that packet).
  • SR dilemma: Sequence number space must be at least twice the window size to avoid ambiguity.

3.5 Connection-Oriented Transport: TCP

  • TCP: Point-to-point, reliable, in-order byte stream, pipelined, full duplex, connection-oriented, flow controlled.
  • TCP segment structure: Source port, dest port, sequence number, acknowledgement number, header length, flags (URG, ACK, PSH, RST, SYN, FIN), receive window, checksum, urgent data pointer, options, data.
  • TCP seq. numbers, ACKs: Sequence number = byte stream number of first byte in segment's data; ACK = seq # of next byte expected; cumulative ACK.
EstimatedRTT = (1−α)·EstimatedRTT + α·SampleRTT
DevRTT = (1−β)·DevRTT + β·|SampleRTT − EstimatedRTT|
TimeoutInterval = EstimatedRTT + 4·DevRTT
(typical: α = 0.125, β = 0.25)
  • TCP fast retransmit: 3 duplicate ACKs → resend unacked segment with smallest seq #.
  • TCP flow control: Receiver advertises free buffer space (rwnd); sender limits in-flight data to rwnd.
  • TCP connection management: 3-way handshake (SYN, SYNACK, ACK); closing (FIN, ACK).
  • RST flag: Sent when host receives SYN for a port it doesn't accept.
  • SYN outcomes: SYNACK received, RST received, or nothing (blocked by firewall).
  • TCP congestion control: cwnd; slow start (exponential increase), congestion avoidance (linear increase), fast recovery.
    • AIMD: Additive increase, multiplicative decrease.
    • TCP Tahoe: Cut cwnd to 1 MSS on timeout or triple duplicate ACK.
    • TCP Reno: Fast recovery.
avg TCP throughput = (3/4) · W / RTT   bytes/sec
  • TCP fairness: K TCP sessions share bottleneck link of bandwidth R, each gets R/K.

Example Questions and Solutions

Chapter 1 Examples

Q: Circuit-switching with 20 Mbps users on 100 Mbps link — max users?

A: 100 / 20 = 5 users.

Q: Packet-switching, 9 users, each transmits 30% of time. Can circuit-switching support 9?

A: No — 9 × 20 = 180 Mbps > 100 Mbps.

Q: Probability one specific user transmitting, others not (9 users, p = 0.3)?

A: p·(1−p)N−1 = 0.3 × 0.78 = 0.017.

Q: Probability exactly one user transmitting (any of 9)?

A: N·p·(1−p)N−1 = 9 × 0.3 × 0.78 = 0.153.

Caravan Example: 10 cars, toll booth 1 car/2 s, 500 km at 20 km/s.
  • Service time per car: 2 s.
  • Entire caravan service: 20 s.
  • Travel to next booth: 25 s.
  • First car serviced at next booth: 18 + 25 = 43 s.
  • Two cars in service simultaneously? No.
  • Zero cars in service? Yes (when last car is travelling).
